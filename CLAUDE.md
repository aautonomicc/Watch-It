# Watch-It

## Description
Cross-platform media player (Android, Android TV, iOS, Linux, Windows, macOS) for the Autonomi network. Client-only — no server side at all, and no Plex/Emby/Jellyfin server compatibility (stripped by design). Plex-style poster-wall UI.

## Tech Stack
Flutter 3.44.6 (SDK at ~/flutter) + media_kit (libmpv); SQLite via drift (media lists; codegen: `dart run build_runner build` in app/); Riverpod planned; Autonomi access via embedded Rust library `native/watchit_core` (ant-core, dart:ffi + in-process localhost streaming server) — no gateway/sidecar. `media_kit_video` is vendored at `app/third_party/media_kit_video` (pubspec dependency_overrides) carrying a Linux H/W-rendering patch — see Architecture Notes; drop when upstream fixes media-kit/media-kit#1404.

## Test Commands
In `app/`: `flutter analyze`, `flutter test` (PATH needs `~/flutter/bin`; `source ~/Android/env.sh` for Android builds). Live TMDB tests (test/tmdb_live_test.dart) need the credentials from the gitignored repo-root `.env`: `set -a; source ../.env; set +a; flutter test` — skipped automatically when TMDB_API_KEY is unset (CI needs no secrets). Dev build with the key bundled: `flutter run -d linux --dart-define-from-file=../.env` (dev/live-test only). Releases are KEYLESS since 2026-07-25 (user decision, reversing the alpha.24 bundling): release_build.sh no longer sources .env or passes any --dart-define, and `AppSettings.bundledTmdbApiKey` is deleted — users add their own key via Settings → Metadata (TmdbKeySource is now user|none). ⚠️ the old key IS extractable from published alpha.24–.33 binaries — rotate it on TMDB after the first keyless release ships. Release builds: run `scripts/release_build.sh` — it re-execs itself as transient systemd user unit `watchit-build` (survives session death; linger is on), builds APK then AppImage, logs to /tmp/watchit-build.log, refuses to double-launch. Follow with `tail -f /tmp/watchit-build.log`, status via `systemctl --user status watchit-build`; "ALL BUILDS DONE" in the log = success. Rust: `cargo test` in `native/watchit_core/` (needs `~/.cargo/bin` in PATH). Before `flutter build apk`: run `native/build-android.sh` (cargo-ndk → jniLibs). Host streaming harness: `cargo run --release --bin devserver` then curl `/health` and `/xor/<addr>`.

## Dev Server
`flutter run -d linux` in `app/` — Linux desktop toolchain installed (clang/ninja/libgtk-3-dev/libmpv-dev); Android also fully working. AppImage: `scripts/build_appimage.sh` (needs linuxdeploy at ~/tools/, output in dist/, gitignored).

## Architecture Notes
- Library = user-held **lists**; each entry is `{derived address, file name}` — DATAMAP-FIRST since alpha.40 (docs/PLAN-datamap-privacy.md): content enters ONLY via `.datamap` files (private `ant file upload` output, bare msgpack root DataMap; legacy ant-gui JSON sniffed by `{`) or `.watch-list` bundles; the address is blake3(rmp(shrink(root))) derived OFFLINE by `POST /datamap` (verify.rs::derive_address), == the public XOR address for public uploads (validated live against the real NOTLD map: POST of its 108KB datamap derives 66cacd06…cb13 exactly). Root map REQUIRED in the local mapstore; `/xor/{addr}` serves stored maps only and fast-fails 404 "data map missing — re-import" (no network resolve on the play path, kills the 20-31s cold resolve). Public XOR addresses REMOVED as entry type: no add-entry dialog (and since 2026-08-03 the list editor has NO add button at all — the Media page's "Add to library" is the single import entry point, which also creates lists), no plain-.txt import/export, no DataMapPrefetcher/prefetch dialogs/tile-open warm (all deleted; wiMessengerKey moved to widgets/messenger.dart). `GET /resolve/{addr}` is a LOCAL-store {size,chunks} lookup since alpha.41 (404 for never-imported; kept only for the download manager) — data_map_fetch, the v1 border conversion, library_migration.dart, and bundle-download-by-address were all deleted in alpha.41 (releases 2+3). Bundle spec v2 (docs/BUNDLE-FORMAT.md): `datamaps/<original filename>.datamap` members (zip root accepted — hand-made `zip lib.watch-list *.datamap` is valid), optional filename-line list.txt (`ListName=` + lines ending .datamap; hex lines = v1 → SKIPPED since alpha.41, all-v1 files error "re-export from 0.1.0-alpha.40+", rootmaps/ members ignored), unclaimed members → list named from bundle filename (prompt when network-fetched); export = bundle only from `GET /datamap/{addr}` (ant-cli-compatible msgpack), history checkbox kept, includeRootMaps/pre-resolve pass gone. Widget tests fake the embedded server via HttpOverrides (test/fake_embedded_http.dart — real sockets deadlock in the fake-async zone; XFile.fromData ignores `name:`, use `path:`)
- Lists live in SQLite via drift: lib/db/app_database.dart (tables media_lists/media_entries, position columns keep order; generated code checked in) behind the unchanged LibraryStore load/save/ensureDefaults API. media_lists.enabled (schema v3, default 1) drives per-list home-screen visibility; lists are managed on the dedicated Settings → Media Lists page (screens/media_lists_screen.dart: create, checkbox show/hide, rename/delete behind a 3-dot menu; tap opens ListEditScreen). DB file `watchit.sqlite` pinned to getApplicationSupportDirectory (drift_flutter's documents-dir default degrades to $HOME on headless Linux). First open imports the legacy `media_lists_v1` shared_preferences JSON blob into an empty DB, then removes the key; `defaults_seeded_v3` flag stays in shared_preferences so upgraded installs don't re-seed. Tests inject `AppDatabase.forTesting(NativeDatabase.memory())` via LibraryStore.useForTesting
- Metadata matcher (alpha.23, lib/services/metadata_service.dart + tmdb_client.dart): file name → parseMediaName (title/year/imdb-id/SxxEyy + 1x02 markers) → TMDB (exact /find by IMDb id, else title/year search; TV gets show + episode details) → artwork/description/category, cached in SQLite (metadata_cache table, keyed by ParsedName.lookupKey so renames share rows; misses cached with 7-day TTL, transport errors never cached) with w342 posters as files in <support>/posters/. BYO TMDB key: Settings → Metadata accepts v3 api key (query param) or v4 read token (dots → Bearer header); `--dart-define=TMDB_API_KEY` bundles a default. Screens call the sync MetadataService.instance.metadataFor inside a ListenableBuilder; fallback chain memory → bundled NOTLD catalog → parsed name. Key change calls reset() (clears misses). schemaVersion 2 (onUpgrade creates the table)
- Playback via libmpv (media_kit) everywhere; streams `http://127.0.0.1:<port>/xor/<addr>` from the embedded client — seek works via HTTP Range
- Linux H/W video rendering (alpha.18 + alpha.20): vendored media_kit_video patch — upstream reads Flutter's EGL display with eglGetCurrentDisplay() on the platform thread, which returns EGL_NO_DISPLAY since Flutter 3.38, so every Linux box silently fell back to CPU mpv rendering + pixel-buffer copies (the Mint jerky-video/janky-spinner report). Fix: init stays EAGER on the platform thread (upstream flow) but derives Flutter's EGLDisplay exactly like the embedder's fl_opengl_manager.cc does — eglGetPlatformDisplayEXT(EGL_PLATFORM_WAYLAND/X11_EXT, gdk native display) returns the identical EGLDisplay handle; Flutter's *context* is never needed since the mpv render context lives in an isolated unshared context (only the display must match, for the display-scoped EGLImage frame sharing). Two hard-won invariants: (1) do NOT defer init to the first FlTextureGL populate — deadlock: Video widget mounts the Texture only after mpv reports dimensions, mpv reports dimensions only after the render context exists, the render context was only created in populate, and populate only runs when the Texture is composited (alpha.17's black-screen/stalled-playback bug); (2) after init on the platform thread, RELEASE the isolated context (eglMakeCurrent(dpy, NO_SURFACE, NO_SURFACE, EGL_NO_CONTEXT)) — restoring the saved EGL_NO_DISPLAY binding is an error that leaves our context current there and every raster-thread eglMakeCurrent then fails EGL_BAD_ACCESS; (3, alpha.20) on real-GPU X11 boxes GTK presents FlView through a GDK **GLX** context and leaves it current on the platform thread after painting — EGL cannot see a GLX binding (eglGetCurrentContext()==EGL_NO_CONTEXT) but Mesa refuses to bind an EGL context over it (EGL_BAD_ACCESS 0x3002 → S/W fallback, the Mint alpha.19 report), so video_output_release_foreign_gl_binding() calls gdk_gl_context_clear_current() before binding the isolated context (init + dispose); GDK re-binds on its next paint. xvfb NEVER exercises the GLX case (no DRI3 → no GDK-GL) — real-GPU testing needs the harness's REPRO_GDK_GL=1 runner hook that pins a GdkX11GLContext current before plugin init. Files: linux/video_output.cc (video_output_init_hw, video_output_get_flutter_egl_display, video_output_release_foreign_gl_binding), linux/texture_gl.cc (pure upstream populate). Verified via /tmp/mk_repro harness under xvfb (raw Texture + stock Video widget + upstream control + REPRO_GDK_GL both-ways test)
- Embedded client: `native/watchit_core` (Rust cdylib, ant-core 0.5.1 pinned rev 81a0a24) — tokio runtime + axum server on 127.0.0.1, `GET /xor/<addr>` (Range via self_encryption streaming_decrypt/get_range), `GET /health` for the Settings status tile; started once from main() over dart:ffi (lib/services/embedded_client.dart). APK is arm64-v8a only (abiFilters + jniLibs excludes); jniLibs/ and target/ are gitignored build artifacts
- Chunk cache + keep-ahead prefetch (post-alpha.20): all chunk traffic goes through a process-wide byte-bounded LRU (`cache.rs`, 256 MiB desktop / 128 MiB Android, single-flight claims so serving+prefetch never double-download; waiters poll 50ms — deliberate, avoids Notify lost-wakeup). Each `stream_range` spawns `prefetch_ahead` (engine.rs): serving loop reports last-served byte via a watch channel, prefetcher keeps PREFETCH_AHEAD_CHUNKS=16 (~64 MiB ≈ 60-70s at 7-8 Mbps) warm at PREFETCH_CONCURRENCY=4 (< FETCH_CONCURRENCY=16 so foreground batches win). Prefetch caps at the request's `end` — fine because mpv sends open-ended ranges. Prefetcher exits when serving drops the watch sender; chunk offsets rebuilt from DataMap::infos() cumulative src_size (same mapping get_range uses). /health gained cache_hit_chunks + cache_bytes
- Root-map persistence + prefetch (post-alpha.27): resolved root data maps persist in SQLite (`mapstore.rs`, rusqlite bundled, `root_maps.sqlite` in the app data dir, addr BLOB → bincode DataMap via DataMap::to_bytes) — content-addressed and immutable so cached forever; `Engine::root_map` reads memory → disk → network and writes back both, so any title's map resolves over the network at most once per device (cold resolve of the 5.3GB movie ≈ 22-31s, disk hit ≈ 7ms, across app restarts). `GET /resolve/{addr}` resolves+persists without streaming (returns `{size, chunks}`); `/health` gained `stored_maps`. Flutter: after a list import the Media Lists page offers "Prefetch data maps?" (DataMapPrefetcher walks the imported entries sequentially through /resolve; progress dialog = spinner + `File X of N` + file name + Cancel; declining costs nothing — maps persist on first play anyway). `Engine::new`/`start()` take the data dir; devserver honours WATCHIT_DATA_DIR
- Android $HOME shim (alpha.7): `watchit_core_start(peers_csv, data_dir)` — Dart resolves getApplicationSupportDirectory() in main() (awaited before runApp so no lazy start can race it) and the native side sets HOME/XDG_DATA_HOME/XDG_CONFIG_HOME to it before any ant-core code runs (temp-dir fallback when NULL). Needed because ant-core's config::data_dir unwraps the home-dir lookup → HomeDirNotFound panic on Android; peer cache persists in the app dir as a side benefit
- Connect hardening (alpha.6): each `Client::connect` attempt runs in its own task (panic→error) with 60s timeout; saorsa-core returns Ok with 0 peers when all bootstrap dials fail — engine treats that as failure; reconnect supervisor (2026-07-30): client lives in RwLock<Option<Arc<Client>>>, supervise() re-dials with 2s→60s backoff and evicts on 0 peers x2 polls (POST /reconnect kicks it); `/health` while connecting = `{state, attempts, message}`; panics routed to tracing (logcat tag `watchit_core`). Devserver takes `WATCHIT_PEERS=ip:port` to test the failure path
- Download manager (post-alpha.29, lib/services/download_manager.dart): pure Dart, no Rust changes — streams `GET /xor/<addr>` (deterministic decrypted bytes) to disk one task at a time, resuming partial files with `Range: bytes=<file length>-` (the file on disk, not the DB counter, is the resume offset; progress persists only after flush). Queue persists in the `downloads` drift table (schema v6, address PK); mid-flight rows re-queue on next launch, paused stay paused. Files land in `<support>/downloads/` (Android app-private, no permissions) or a user-chosen desktop folder (Settings → Downloads, file_selector, new downloads only); duplicate names get an addr-prefix. Total size pre-filled via `/resolve` at enqueue. UI: DetailScreen Download button cycles start/pause/resume/retry/remove with a progress bar; Settings → Downloads = queue + pause/resume-all + storage + behaviour. A finished download plays locally: DetailScreen resolves local-path-beats-streamUrl (also for Up-next chaining via PlayerScreen.sourceFor; isLocal skips the network buffering overlay + health poll). Streamed playback with active downloads applies PauseDownloadsOnPlay (ask/always/never, "remember my choice" writes the pref; chained episodes never re-prompt); pauseAllForPlayback tracks exactly what it paused so resumeAfterPlayback (player close, "Downloads resumed" snackbar) spares manual pauses. Race gotcha: resume() can land before an aborted transfer's error surfaces — the catch treats status queued like paused (keep bytes, let the pump retry), else it would mark the re-queued task error. Connection loss auto-pauses instead of erroring: a failed transfer probes `/health` and pauses (no error text) when the client is `connecting` or `ready` with 0 peers; a 2-minute no-data stall timeout on the body stream backstops streams that hang instead of erroring. System pauses (connection loss, waiting-for-Wi-Fi, 6h Android timeout) are flagged pausedBySystem (schema v7) and auto-resume on reconnect/Wi-Fi/app-resume/next-launch; user pauses stay manual
